# КТ-4 — интеграционное тестирование eShopOnWeb

Отдельный стенд для проверки интернет-магазина методом «большого взрыва».
До выполнения сценариев соединяются Web, PublicApi, бизнес-логика, репозитории
и SQL Server. Подготовка БД выполняется до старта Web, чтобы два приложения
не применяли одни миграции одновременно. Это порядок запуска инфраструктуры,
а не поэтапная замена компонентов заглушками.

## Исходный проект

Используется [dotnet-architecture/eShopOnWeb](https://github.com/dotnet-architecture/eShopOnWeb)
из задания, ревизия `4da8212117e87d808d4bbc7da6286fd2147ce606`, лицензия MIT.
Исходники загружаются в `.upstream/` и не включаются в этот репозиторий.
`upstream.lock.json` закрепляет commit и digest образов SDK, ASP.NET Core и SQL Server.
Лицензия исходного приложения сохраняется внутри собранных образов.

| Компонент исходного проекта | Назначение и связи |
| --- | --- |
| Web | Razor Pages и MVC, каталог, корзина, оформление и просмотр заказов |
| ApplicationCore | Модели каталога, корзины и заказов, бизнес-сервисы и контракты репозиториев |
| Infrastructure | EF Core, SQL Server, реализация репозиториев, ASP.NET Core Identity |
| PublicApi | HTTP API каталога и авторизации для административного интерфейса |
| BlazorAdmin и BlazorShared | Административный интерфейс, клиент API и общие DTO |
| SQL Server | Две базы: `KT4Catalog` для каталога и заказов, `KT4Identity` для пользователей |

Область КТ-4 — приложение eShopOnWeb. Правила вымышленного магазина из КТ-3,
включая PayPal, SAVE10 и почтовую доставку, не переносятся на него автоматически.

## Структура

```text
eshop-big-bang/
├── compose.yaml
├── Dockerfile
├── upstream.lock.json
├── environment/              # настройки учебного стенда
├── scripts/                  # подготовка, запуск, проверка и остановка
├── .upstream/                # загруженный оригинал, вне Git
├── .env                      # локальный пароль и образы, вне Git
└── artifacts/                # результаты запусков, вне Git
```

`environment/global.json` заменяет `8.0.x` из upstream конкретной минимальной
версией SDK с переходом на установленный feature band .NET 8. Подмена выполняется
только внутри Docker-сборки. Исходный Git checkout остаётся чистым.

Браузер обращается к API через `localhost:18302`, а контейнер Web — через
`api:8080`. Отдельный `appsettings.Docker.json` задаёт адреса браузерного Blazor-клиента.
Порты Java-сервисов КТ-2 остаются 18081 и 18082.

## Запуск

Нужны Git, PowerShell 7 и Docker Desktop с Linux containers. Локальный .NET SDK
для контейнерной сборки не требуется. Первый запуск скачивает зависимости.

Из этой папки:

```powershell
./scripts/Start-Environment.ps1
```

Команда загружает закреплённую ревизию, создаёт `.env`, собирает приложения,
поднимает SQL Server и API, затем Web и проверяет доступность компонентов.
Случайный пароль БД хранится только в `.env`; SQL Server не публикует порт на хосте.
Web и API доступны только на локальном компьютере.

- Магазин: http://localhost:18301/
- Административная часть: http://localhost:18301/admin
- Swagger: http://localhost:18302/swagger/
- Состояние Web и его связей: http://localhost:18301/health

Учебные пользователи исходного проекта: `demouser@microsoft.com` и
`admin@microsoft.com`, пароль `Pass@word1`. Эти опубликованные демонстрационные
данные предназначены для локального стенда.

## Проверка и остановка

```powershell
./scripts/Test-Environment.ps1
docker compose ps
docker compose logs --tail 80 web api
./scripts/Stop-Environment.ps1
```

`Test-Environment.ps1` проверяет каталог в Web и API, `/health`, Swagger и адрес
API в конфигурации браузера. Результат записывается в
`artifacts/environment-check.json`. Это проверка готовности стенда;
полный набор сценариев КТ-4 добавляется отдельным этапом.

В контейнере Web используется тот же порт 18301, что и на хосте: штатная проверка
главной страницы строит URL из входящего HTTP-заголовка Host и вызывает его из Web.

Остановка сохраняет базы в томе `kt4-eshop_database`. Повторный запуск использует
те же данные. Для проверки на пустой БД можно запустить отдельный Compose-проект
с новым именем, предварительно остановив этот стенд для освобождения портов.

Отчёт КТ-4 в формате DOCX и доказательства выполнения хранятся в соседней папке
`КТ4/`, вне Git. Перед итоговым отчётом нужны собственные сценарии и фактические
результаты их выполнения; штатные тесты upstream учитываются отдельно.
